model_write_lock

acquire exclusive write locks for the object models of given backends.

model changes (ex.: REST /config/objects or the config tool cgi pages) are read-modify-write on the shared storable retention files, so concurrent requests from other FCGI workers or forked jobs would race and drop each others objects (see #1497). This lock serializes the whole read-modify-write for the duration of the current request, the short file locks in get_model_retention()/store_model_retention() only protect the storable files themselves.

Retry a few times before failing, so short concurrent writes get serialized instead of an error. The returned error is a hash which can be passed to $c->detach_error (rest: 409), or used as is for html error pages (503).

Returns 1 on success, the error hash on failure. The locks are released when the filehandles get destroyed at the end of the request (including when detach_error() dies).
